## Description {/* #descripcion */}

A component responsible for maintaining an organized collection of information, structured according to a defined model and managed by a specialized system (DBMS). Its purpose is to store, maintain, and make available the data that represents the state of the information system, ensuring its persistence, integrity, security, and availability. It receives information from the inputs, is updated by the autonomous processes, and is queried by the outputs.

- **Replication:** keeps synchronized copies of the data on multiple nodes for high availability or geographic distribution
- **Automatic backups:** generates periodic backups of the content for recovery from failures or data loss
- **Schema migrations:** allows the structure of the data to evolve without losing information, applying changes in a controlled way
- **Indexing:** speeds up queries at the cost of additional space by maintaining auxiliary search structures

## Boundaries {/* #delimitaciones */}

<Admonition type="danger" title="What it is not">

- Its management and operational control are carried out by specialized systems (DBMS), which are not directly part of this component
- **Does not** define the access policies or permissions on the stored data — that belongs to [Authorization](/docs/componentes/autorizacion)
- **Does not** cover temporary or cache repositories

## Variants {/* #modalidades */}

- **Relational database:** models data as tables with explicit relationships through keys; based on SQL
- **Non-relational database:** stores data without a rigid schema (key-value, document, columnar)
- **Navigational / graph database:** models data as nodes and explicit relationships, optimized for connectivity queries
- **Object-oriented database:** stores data as objects with attributes and methods, aligned with object-oriented programming paradigms
- **Vector database:** optimized for storing and searching high-dimensional embeddings, common in AI applications
