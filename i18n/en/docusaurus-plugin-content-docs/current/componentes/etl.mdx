## Description {/* #descripcion */}

A component that brings information from sources outside the information system into it, adapting it to the internal data model. Its function is to ensure that the incoming data is consistent, up to date, and compatible with the structure of the system. To do so, it performs three tasks: it extracts the data from its original sources, transforms it according to business rules or intended uses, and loads it into the destination store.

## Additional capabilities {/* #capacidades-adicionales */}

<div className={styles.capBlockOptional}>

<div className={styles.capHeading}>
  <svg viewBox="0 0 16 16" width="16" height="16" fill="currentColor"><path d="M8 1a7 7 0 1 1 0 14A7 7 0 0 1 8 1zm.5 3.5a.5.5 0 0 0-1 0V7.5H4.5a.5.5 0 0 0 0 1H7.5v3a.5.5 0 0 0 1 0V8.5h3a.5.5 0 0 0 0-1H8.5V4.5z"/></svg>
  <span>Additional capabilities</span>
</div>

- **Periodic scheduling:** runs the ETL at defined intervals (hourly, daily, etc.) through a scheduler, without requiring an explicit trigger
- **Manual trigger:** lets an authorized user start the ETL on demand through an explicit action
- **Activity logging:** records each run (errors, durations, volume of data processed) for auditing and monitoring
- **Automatic retries:** retries failed stages (typically extraction) when facing transient network errors or temporarily unavailable sources

</div>

## Boundaries {/* #delimitaciones */}

<Admonition type="danger" title="What it is not">

- **Does not** define access policies or permissions over the data; it only brings the data into the system
- **Does not** replace the internal processing that derives, calculates, or analyzes information already inside the system ([Scheduled Process](/docs/componentes/proceso-programado) or [Reactive Process](/docs/componentes/proceso-reactivo)): the ETL brings data in from outside; it does not operate on the data already inside
- **Does not** provide an interface visible to the user, although it can be monitored or configured from a console or external service

</Admonition>

## Variants {/* #modalidades */}

- **Batch ETL:** processes large volumes of data in scheduled batches (daily, weekly)
- **Real-time (streaming) ETL:** processes data continuously as it arrives, with low latency
- **ELT (Extract-Load-Transform):** loads the data untransformed and applies the transformations afterward, inside the destination repository

## Typical dependencies {/* #dependencias-tipicas */}

<div className={styles.dependencies}>

- External data source (APIs, servers, sensors, files)
- Destination repository (the system's [Database](/docs/componentes/base-datos))
- A scheduling mechanism or scheduler for running it, when that capability is present
- Business rules that define how the data is handled

</div>
