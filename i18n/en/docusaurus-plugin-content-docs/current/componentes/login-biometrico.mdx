## Description {/* #descripcion */}

A component that lets users identify themselves to the system through unique physical or behavioral characteristics (fingerprint, facial recognition, iris, voice). Unlike traditional credentials, which the user "knows" (a password) or "has" (a device), biometric authentication relies on what the user "is". The system captures the biometric trait, processes it, and compares it against previously enrolled templates to validate the identity.

- Converts the captured characteristics into digital representations (biometric templates) for comparison
- Compares the capture against previously enrolled templates to determine whether the identity matches

## Additional capabilities {/* #capacidades-adicionales */}

<div className={styles.capBlockOptional}>

<div className={styles.capHeading}>
  <svg viewBox="0 0 16 16" width="16" height="16" fill="currentColor"><path d="M8 1a7 7 0 1 1 0 14A7 7 0 0 1 8 1zm.5 3.5a.5.5 0 0 0-1 0V7.5H4.5a.5.5 0 0 0 0 1H7.5v3a.5.5 0 0 0 1 0V8.5h3a.5.5 0 0 0 0-1H8.5V4.5z"/></svg>
  <span>Additional capabilities</span>
</div>

- **Operation as an additional factor (multi-factor):** the component works together with another form of authentication (password, token), adding a biometric layer to an existing flow instead of replacing it
- **Fallback authentication:** lets the user authenticate through a non-biometric mechanism (PIN, password) when biometric verification fails or is unavailable
- **Liveness detection (anti-spoofing):** processes the biometric capture to verify that it comes from a real person and not from an image, a video, or a replica of the trait

</div>

## Boundaries {/* #delimitaciones */}

<Admonition type="danger" title="What it is not">

- **Does not** include the initial registration of the biometric trait (enrollment), which is part of user management
- **Does not** handle authorization or permissions after authentication
- **Is not** applicable to programmatic authentication between systems
- Requires specific technical infrastructure (sensors, matching algorithms) not present in traditional systems

</Admonition>

## Variants {/* #modalidades */}

- **Fingerprint:** scanning and comparison of the unique patterns of the fingerprint
- **Facial recognition:** analysis of facial features through a camera
- **Iris recognition:** identification through the unique patterns of the iris
- **Voice recognition:** authentication through characteristic vocal patterns

## Typical dependencies {/* #dependencias-tipicas */}

<div className={styles.dependencies}>

- Suitable hardware (fingerprint sensor, camera for facial recognition, iris scanner)
- Biometric comparison engine (matching algorithms)
- Repository of enrolled biometric templates ([Database](/docs/componentes/base-datos))
- Session or token manager to maintain authentication after verification
- Fallback authentication mechanism for cases of biometric failure ([Login Form](/docs/componentes/formulario-login))

</div>
