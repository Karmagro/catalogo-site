## Descripción

Componente que ejecuta una rutina de procesamiento sobre datos que **ya residen en el sistema**, sin que un usuario lo opere paso a paso. Toma información interna, le aplica una lógica de transformación, verificación o derivación, y produce un resultado: datos nuevos, datos corregidos o un veredicto. Se dispara de forma autónoma —según una agenda (cada noche, cada hora)— o bajo demanda, cuando otro componente o un operador solicita su ejecución.

Es el componente al que recurre el sistema cuando necesita "hacer un cálculo o una comprobación por dentro" que no encaja en ningún flujo de entrada, salida o aprobación: cruzar entidades para detectar inconsistencias, recalcular totales o saldos, derivar indicadores a partir de datos existentes, depurar registros vencidos. En la industria del software corresponde a la familia de los *background jobs* o *batch jobs*: tareas que corren independientes de la interfaz, lanzadas por la aplicación y monitoreadas, no operadas, por las personas.

Lo que da forma a este componente es el **cómo** (procesamiento autónomo sobre datos internos, con un disparador de agenda o solicitud), no el **qué**: igual que un Mantenedor no fija qué entidad administra ni una Consulta qué se consulta, un Proceso Interno no fija qué calcula. Ese dominio abierto lo hace genérico, no informe.

- Ejecuta una lógica de procesamiento sobre datos que ya están en el sistema, sin intervención humana en sus pasos
- Se activa mediante un disparador: programado (según una agenda) o bajo demanda (a solicitud de otro componente o de un operador)
- Produce un resultado a partir del procesamiento: datos derivados, datos corregidos, o un veredicto (válido/inválido, conciliado/no conciliado)
- Opera en segundo plano, sin ocupar ni bloquear la interacción del usuario con el sistema

## Capacidades adicionales

<div className={styles.capBlockOptional}>

<div className={styles.capHeading}>

  <span>Capacidades adicionales</span>

- **Programación periódica (scheduling):** ejecuta la rutina en intervalos definidos mediante un planificador, sin disparo explícito de un usuario
- **Ejecución bajo demanda:** permite que un operador o componente solicite la ejecución en el momento (por ejemplo, "recalcular ahora", "verificar integridad ahora")
- **Emisión del resultado:** entrega el resultado al solicitante (cuando es bajo demanda) o lo comunica de forma proactiva (alerta de inconsistencia, aviso de finalización)
- **Logging de actividad:** registra cada ejecución (tiempos, volumen procesado, errores) para auditoría y monitoreo
- **Reintentos y checkpoints:** reanuda o reintenta el procesamiento ante una interrupción, retomando desde el último punto guardado

</div>

## Delimitaciones

<Admonition type="danger" title="Qué no es">

- **No incorpora datos desde fuera del sistema.** Opera sobre los datos que ya están adentro. Si la rutina trae datos de una fuente externa, eso es un [ETL](/docs/componentes/etl) o un [Scraper](/docs/componentes/scraper), no un Proceso Interno.
- **No involucra decisiones humanas en sus pasos.** Si el procesamiento se detiene para que una persona apruebe, rechace o derive en alguna etapa, es un [Workflow de aprobación](/docs/componentes/workflow-aprobacion), no un Proceso Interno.
- **No es una salida de información al usuario.** Una [Consulta](/docs/componentes/consultas) o un [Reporte](/docs/componentes/reporte) responden a una solicitud entregando datos existentes; el Proceso Interno *genera* datos o veredictos mediante cómputo, aunque pueda apoyarse en esos componentes para entregar su resultado.
- **No es el "cajón de sastre" del catálogo.** No es "todo lo que no cae en otro componente": tiene una forma definida (procesamiento autónomo sobre datos internos). Lo que queda abierto es el dominio del cálculo, igual que en el resto de los componentes.

</Admonition>

## Modalidades

- **Programado (schedule-driven):** un planificador lo invoca de forma recurrente o en un momento fijo (cierre nocturno, conciliación diaria, depuración semanal).
- **Bajo demanda (event-driven):** se dispara ante una solicitud explícita o un evento del sistema ("verificar integridad ahora", recalcular tras un cambio masivo).
- **Por lotes (batch):** procesa grandes volúmenes de registros internos de una vez, frecuentemente en una ventana de baja carga.

## Dependencias típicas

<div className={styles.dependencies}>

- Repositorio de datos del sistema ([Base de Datos](/docs/componentes/base-datos)) sobre el que lee y escribe
- Mecanismo de programación o scheduler para su ejecución programada, cuando esa capacidad está presente
- Reglas de negocio que definen la lógica de transformación, verificación o derivación
- [Sistema de Notificación](/docs/componentes/sistema-notificacion) cuando el resultado se comunica de forma proactiva

</div>
